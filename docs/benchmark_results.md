# OL-SCS vs frame-level SCS — 벤치마크 결과

- 측정일: 2026-10-20 · RTX 4060 · YOLOv5s (torch) · 1280×720
- 코드: `10d90ec` (OL-SCS I/P, proc_width 160) · `eval_accuracy.py`
- 재현:
  ```bash
  python benchmark.py --videos <video> --out results/<dir>
  python eval_accuracy.py --video <video>
  ```

## 지표

| 지표 | 정의 |
|---|---|
| FPS | 처리 프레임 / 파이프라인 지연시간 합 (스케줄러+탐지+차선+제어, 디코딩 제외) |
| 속도비 | olscs FPS / frame FPS |
| recall | 매 프레임 전체 추론 결과(기준) 중, 스케줄러 출력과 같은 클래스·IoU ≥ 0.5로 1:1 매칭된 비율 |
| precision | 스케줄러 출력 중 기준과 매칭된 비율 (사라진 객체를 계속 내보내면 ↓) |
| recall_P | P-frame(재사용)만 집계한 recall |

## 해석

- **dashcam · highspeed**: 더 적은 I-frame으로 frame 모드와 같거나 약간 높은 정확도. 속도 이득이 정확도
  손실 없이 나온다. (P-frame만 보면 highspeed recall_P는 0.628 vs 0.634로 비슷)
- **lowlight**: 1.59× 빨라졌지만 recall −9.5%p. I 비율이 10%까지 내려갔고 원인 대부분이 재사용 한도·주기로,
  객체 움직임 판정은 175회뿐이다. 어두운 영상에서 밝기 차가 `pixel_thresh=20`을 잘 넘지 못해
  움직임을 놓치는 것으로 보인다 (가설 — 미검증).
- **crowd**: 배경 변화 판정(106회)이 I-frame을 늘려 느려졌다. 대신 정확도는 가장 많이 올랐다.
- P-frame 판정 비용은 여전히 frame 모드보다 ~0.2ms 크다 (0.52–0.58 vs 0.32–0.35ms).
- 파라미터는 dashcam.mp4 기준으로 조정되었다.
